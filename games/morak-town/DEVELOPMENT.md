# 모락모락 타운 개발 지침서

이 게임을 이어서 개발하는 사람과 AI 도구가 지켜야 할 기준이다. 작업을 시작하기 전에 이 문서를 먼저 읽는다. 무엇을 만들지는 [ROADMAP.md](ROADMAP.md)를, 게임 소개는 [README.md](README.md)를 본다.

이 폴더는 저장소의 주식 앱(`partisan_investment.html`, `GEMINI.md` 등)과 독립적이다. 서로 파일을 공유하지 않으며, 주식 앱의 키·계좌·주문 기능에는 손대지 않는다.

---

## 1. 게임의 정체성

- **장르:** 한국 F&B 시장을 운영하는 힐링 경제 시뮬레이션. 작은 가게 하나에서 시작해 프랜차이즈 기업이나 한 매장의 장인으로 성장한다.
- **무대:** 바닷가 강 하구의 가상 소도시 "모락 베이". 서울을 재현하지 않는다. 유럽풍의 낮은 건물, 모래사장, 트램, 시계탑 광장이 있는 여유로운 동네다.
- **분위기:** 확대했을 때 하나의 잘 꾸며진 유기적인 마을처럼 보여야 한다. 사람들은 바쁘게 일하기보다 산책하고, 달리고, 출근하고, 벤치에 앉고, 잔디에 눕고, 해변에서 태닝한다.
- **오픈월드:** 확대하면 매장 안이 지도 위에서 그대로 보이고, 길을 걷던 손님이 실제로 문으로 들어간다. 별도 화면(매장 모달)은 관리용이고, 지도와 같은 가구 배치를 보여준다.
- **참고 감각:** 그림과 거리 연출은 니펫츠(Nippets) "도시의 봄", 상권과 매장은 Coffee Inc 2, 생산 사슬은 Capitalism Lab, 메뉴 발견과 셰프 성장은 카이로소프트. 참고만 하고 이름·캐릭터·그림·레벨을 베끼지 않는다.

## 3. 명칭 원칙

- 실존 기업·방송·평가 제도·상표·지명을 그대로 쓰지 않는다. 떠올릴 수는 있게 하되 이름은 모두 가상으로 짓는다.
  - 예: 셰프 경연 방송 → "흑과 백 사이"(가칭), 미식 가이드 → "별빛 가이드", 게임 속 SNS → "모락그램"(가칭).
- 지명은 부드럽고 따뜻한 한국어 이름으로 짓는다(해바라기언덕, 고양이언덕, 수국언덕, 조개해변 등).
- "가칭"으로 둔 이름은 사용자와 확정하기 전까지 가칭으로 표시한다.

## 4. 아트 디렉션

### 4-1. 기본 규칙
- **선:** 모든 형태는 진한 자주색 잉크 외곽선(`INK = #5e1f2b`)으로 그린다. 선은 둥근 끝(`lineCap: round`)을 쓴다.
- **면:** 그라데이션 없이 납작한 색면만 쓴다. 그림자는 반투명 잉크색 타원 하나다.
- **투영:** 2:1 아이소메트릭. 타일 `TW=64, TH=32`. 좌표 변환은 `iso(x, y)` 하나만 쓴다.

### 4-2. 색
| 용도 | 색 |
| --- | --- |
| 잉크 | `#5e1f2b` |
| 크림(창틀·간판·종이) | `#fff4ea`, `#fff8ee` |
| 벽 | 먼지 낀 분홍 `#e58ba3`, 라벤더 `#a99bd9`, 겨자 `#e3a63c`, 산호 `#e46b5f`, 하늘 `#9ea7de`, 살구 `#f0b6a8` |
| 지붕 | `ROOFC`: 슬레이트 `#6f7fa8`, 테라코타 `#c86a55`, 구리 녹 `#7fa392`, 장미 `#a8647a`, 주황 `#d98a5a` |
| 자연 | 잔디 `#b7c17a`, 나무 `#7d9c55`, 물 `#86c3d3`, 바다 `#7cc6cc`, 모래 `#f3dfb4` |
| 길 | 대로 아스팔트 `#c3adae`, 자갈길 `#dcc7bd`, 인도 `#f1e2dc` |

새 색을 넣을 때는 이 표의 톤(채도 낮고 따뜻한 파스텔)을 벗어나지 않는다.

### 4-3. 건물
- 유럽풍 저층(대부분 2~7층). 고층 유리 빌딩은 만들지 않는다.
- 쓰는 장식: 크림 창틀과 꽃상자(`winBoxes`), 지붕선 물결 장식(`scallop`), 현관 계단(`stoop`), 밑동 덤불(`hedge`), 망사르드 지붕과 지붕창·굴뚝(`mansard`), 박공지붕과 둥근 창(`gable`), 평지붕 위 생활(`roofLife`: 화분·실외기·선베드·비둘기).
- 한 종류의 건물도 `hash(x, y)`로 색·지붕·장식을 바꿔 같은 모양이 반복되지 않게 한다.
- 매장 겉모습: 회사 색 차양, 간판(업종 아이콘 + 회사 로고), 입간판, 테라스.

### 4-4. 사람
- 가늘고 긴 몸. 피부색·머리 모양·바지·셔츠를 사람마다 다르게 한다(`SKIN`, `HAIR`, `PANTS`, `SHIRTS`).
- 거리: 산책(느림), 러닝(빠름, 아침·저녁, 운동복과 머리띠), 출근(평일 출퇴근 시간, 서류가방), 둘이 걷기, 강아지 산책, 매장에서 나온 사람(컵).
- 공원·해변(정지 그림): 벤치에 앉은 사람, 잔디에 누운 사람, 돗자리 소풍, 선베드, 태닝.
- 밤과 겨울에는 공원·해변의 쉬는 사람을 줄인다.

### 4-5. 매장 내부
- 두 벽(벽 두께 표시) + 판자 바닥(홀) + 체크 타일(주방) + 잉크 외곽선.
- 벽 장식: 커튼 창(바깥 하늘은 시간대 색), 메뉴판, 선반, 시계, 액자.
- 가구는 모두 `Sim.FURN` 목록에 있고 `drawF`의 `case`로 그린다. 매장 모달과 지도 단면이 **같은 함수**로 그린다.

### 4-6. 아이콘
- 모든 아이콘은 `js/icons.js`의 24×24 선 경로다. 채움 없이 선만 쓴다(선 굵기 1.7~2).
- 화면 HTML에 이모지를 쓰면 `Icons.watch(document.body)`가 자동으로 선 아이콘으로 바꾼다. 캔버스에서는 `icon(ctx, 이모지, x, y, 크기)`를 쓴다.
- **새 이모지를 쓰면 반드시 `icons.js`의 `P`(경로)와 `MAP`(이모지 → 이름)에 추가한다.** 목록에 없는 이모지는 컬러 이모지로 그대로 보인다.
- 다음 글자는 아이콘으로 바꾸지 않고 글자로 둔다: `✕ ✓ → ↓ ↻ ★ ☆ ❚ ♪ ⤢ ▶`.

## 5. 코드 구조

빌드 도구와 외부 라이브러리가 없다. `index.html`이 아래 순서로 일반 스크립트를 불러온다.

| 파일 | 역할 | 규칙 |
| --- | --- | --- |
| `js/icons.js` | 선 아이콘 모음, 이모지 자동 교체 | DOM이 없어도 불러올 수 있어야 함 |
| `js/sim.js` | 시뮬레이션 전부 | **DOM·캔버스·`Math.random` 금지.** Node에서도 돌아감. 같은 시드면 같은 결과 |
| `js/render.js` | 도시·매장 내부 캔버스 렌더러 | 시뮬레이션 상태를 바꾸지 않음(읽기만) |
| `js/audio.js` | Web Audio 음악·효과음 | 음원 파일 없음 |
| `js/ui.js` | 패널, 입력, 게임 루프, 저장 | 상태 변경은 `Sim.*` 함수로만 |
| `style.css` | 화면 스타일 | 뒤쪽 블록이 앞쪽을 덮어씀(v4 → v5 순서) |
| `test/sim.test.cjs` | 시뮬레이션 점검 | 기능을 넣으면 점검도 넣음 |

### 5-1. 상태(`S`)
- `S`는 JSON으로 그대로 저장된다(`Sim.serialize`/`deserialize`). 함수·DOM·순환 참조를 넣지 않는다.
- 계산용 캐시는 `S`에 넣지 말고 `WeakMap`이나 렌더러 쪽 `Map`에 둔다(예: `FXC`, `R.doors`).
- 난수는 `rnd(S)`만 쓴다. 렌더러의 연출용 난수는 `Math.random`이나 `hash()`를 써도 된다.

### 5-2. 지도
- 80×80 타일 `S.tiles[y * W + x]`. 타일 종류 `t.t`: `land`, `road`, `bridge`, `water`, `mount`. 길 종류 `t.road`: `ave`(대로), `st`(이면도로), `alley`(골목). 그 밖에 `t.sea`, `t.beach`, `t.bank`.
- 여러 칸 건물: 기준 칸에 `t.b = { k, lv, w, d, v }`, 나머지 칸은 `t.ref`(기준 칸 번호). `fits`, `occupy`, `vacate`, `findFit`, `anchorOf`로만 다룬다.
- 지도 생성 순서(`buildMap`): 강·섬 → 산·호수·바다·모래사장 → 대로 → 강변 → 슈퍼블록 이면도로 → 랜드마크 → `fixRoads` → 강변·해변 공원 → 동네 공원 → 건물 채우기. 공원처럼 꼭 있어야 하는 것은 건물보다 먼저 놓는다.
- 길은 항상 하나로 이어져야 한다(`roadComponents(S) === 1`).

### 5-3. 매장과 가구
- 매장: `S.stores[]`. 업종 `CATS`, 크기 `SIZES`(15·25·40평), 인테리어 `STYLES`·`TIERS`, 건축 양식 `ARCH`.
- 가구: `st.furn = [{ k, x, y, r }]`. 격자 크기 `ROOM[size]`(7×5, 8×6, 9×7). 왼쪽 두 줄은 주방, 오른쪽 앞 모서리 한 칸은 입구.
- `st.furn`이 없으면 기본 배치로 본다(`ensureFurn`). 가구 효과(`furnFx`)는 **기본 배치 대비 차이**로 계산하므로 기본 배치일 때 효과는 항상 중립이다.

### 5-4. 시간
- 시뮬레이션 1스텝 = 게임 1시간(`Sim.step`). 1배속에서 2.5초.
- 우리 매장이 모두 닫힌 밤에는 6배로 빨리 감는다.
- 렌더러는 정지하면 애니메이션 시간도 멈춘다(`adt = 0`).

## 6. 렌더링 규칙

| 확대 배율 | 보이는 것 |
| --- | --- |
| 0.5 미만 | 미리 구운 전체 지도(`bakeOverview`) |
| 0.5 ~ 1.45 | 바닥 구역 캐시 + 건물 그림 캐시 + 움직이는 사람·차 |
| 1.45 이상 | 매장 단면(`drawStoreCut`): 지붕과 앞벽을 걷고 안을 그림 |
| 최대 3.6 | 확대할수록 바닥·건물 캐시를 더 높은 해상도로 다시 그림 |

- **바닥**은 16×16 타일 구역마다 캔버스로 굽는다(`getChunk`). 바닥 그림을 바꾸면 버전 키가 바뀌는지 확인한다.
- **건물**은 정지 그림으로 캐시한다(`spriteFor`). 키는 위치·종류·층수·겨울·밤 단계·배율. 움직이는 연출은 캐시 건물에 넣지 않는다. 매장·시설·움직이는 랜드마크는 매 프레임 그린다.
- **그리기 순서:** 모든 물체를 `d = x + y`(앞 모서리 기준)로 정렬해 뒤에서 앞으로 그린다.
- **매장 안 그리기:** `Renderer.drawInterior(canvas, S, st, opts)` 하나로 모달과 지도를 함께 처리한다. 지도에서는 `opts.embed = { ctx, tw, ox, oy }`로 부르고, 바닥·벽은 `drawStoreCut`이 그린다.
- **손님 입장:** `R.updateShoppers`가 열린 매장마다 시간대별 손님 수에 맞춰 근처 길에서 손님을 보낸다. 경로는 `R.path`(길 BFS), 문은 `R.doorOf(st)`. 들어간 손님은 `R.inside[매장 id]`에 머물다가 컵을 들고 나와 일반 보행자가 된다.
- **성능 기준:** 데스크톱 1440×900과 휴대폰 400×820에서 끊김 없이 돌아야 한다. 보이는 범위 밖은 그리지 않고, 사람·차는 보이는 범위 안에서만 만든다. 휴대폰에서는 사람 수 상한을 낮춘다.
- `prefers-reduced-motion`이면 움직임을 멈춘다(`REDUCED`).

## 7. UI 규칙

- 문구는 쉬운 한국어로 짧게 쓴다. 숫자는 `Sim.won()`으로 표시한다(예: 1.2억원, 3,500만원).
- 상태를 바꾸는 버튼은 `data-act` + `act()` 한 곳에서 처리한다. 결과 메시지는 `result(r)`로 토스트에 띄운다.
- 되돌리기 어려운 행동(폐업, 해고, 기본 배치로 되돌리기)은 두 번 눌러야 실행한다(`arm`).
- 휴대폰(760px 이하)에서는 패널이 아래에서 올라오고 도구 쟁반은 화면 아래에 붙는다. 가로 스크롤이 생기면 안 된다.
- 선은 얇게(1.5px), 면은 평평하게, 그림자는 연하게. 선택된 버튼은 잉크색 채움으로 표시한다.

## 8. 숫자와 밸런스

- 금액은 현실 수준을 따른다. 좋은 자리 카페의 투자금 회수는 3~6개월, 대부분의 음식점은 5~13개월이 기준이다.
- 회계: 부가세 10%, 카드 수수료 1.1%, 인건비 = 시급 × 1.18(4대보험), 감가상각 5년, 법인세 9%/19%, 대출 금리 = 기준금리 + 2.3%p.
- 새 시스템은 **기본 상태에서 기존 밸런스를 바꾸지 않게** 만든다(예: 가구 효과는 기본 배치 대비 차이). 효과를 키울 때는 테스트의 수요·수익 로그를 비교한다.
- 건물 층수를 바꾸면 층당 인구(`popPer`)를 조정해 도시 전체 인구를 유지한다.

## 9. 저장

- 저장 키 `morak.save.v5`(`ui.js`의 `SAVE_KEY`)와 상태 버전 `S.v = 5`(`sim.js`).
- 지도나 상태 구조가 예전 저장과 맞지 않게 바뀌면 둘 다 함께 올리고, `deserialize`의 버전 검사도 바꾼다. 사용자에게 "예전 저장은 불러오지 않는다"고 알린다.
- 맞출 수 있는 변경(새 필드 추가)은 버전을 올리지 말고 없을 때의 기본값으로 처리한다(예: `st.furn`이 없으면 기본 배치).

## 10. 작업 절차

1. `ROADMAP.md`에서 다음 항목을 고른다. 범위가 크면 이번에 할 부분을 정하고 나머지는 계획서에 남긴다.
2. 시뮬레이션(`sim.js`) → 렌더링(`render.js`) → 화면(`ui.js`, `style.css`) 순서로 만든다.
3. 점검을 추가하고 실행한다.
   ```bash
   node games/morak-town/test/sim.test.cjs
   ```
   마지막 줄이 "모든 시뮬레이션 점검 통과"여야 한다.
4. Playwright로 스크린샷을 찍어 눈으로 확인한다. 데스크톱 1440×900과 휴대폰 400×820, 확대 0.7·1.2·2.6배, 매장 모달(가구 배치 탭 포함). 브라우저 오류(`pageerror`)가 0개여야 한다. 사람에게 보여줄 스크린샷은 `deviceScaleFactor: 2`로 찍는다.
5. `README.md`(게임 소개)와 `ROADMAP.md`("완료된 것")를 고친다.
6. 개발 브랜치에 커밋하고 push한다. 커밋 메시지는 한국어로, 첫 줄에 무엇을 했는지 쓰고 아래에 항목을 정리한다.
7. 공개 페이지(아티팩트)를 갱신할 때는 `index.html`에서 `<!doctype>`, `<html>`, `<head>`, `<body>`, charset, viewport 태그를 뺀 본문과 `style.css`, `js/*.js`를 함께 올린다. 새 JS 파일을 만들면 파일 목록에 꼭 넣는다.

## 13. 하지 말 것

- 실존 게임의 이름·캐릭터·그림·음악·레벨을 그대로 가져오지 않는다.
- 실존 상표·방송·평가 제도 이름을 쓰지 않는다.
- `sim.js`에서 DOM, 캔버스, `Math.random`, 현재 시각(`Date.now`)을 쓰지 않는다.
- 렌더러에서 시뮬레이션 상태를 바꾸지 않는다(손님 입장 연출도 렌더러 안에서만 처리하고 매출 계산에는 영향을 주지 않는다).
- 컬러 이모지를 화면에 그대로 남기지 않는다. 아이콘이 없으면 만든다.
- 고층 유리 빌딩, 짙은 그라데이션, 굵은 그림자를 넣지 않는다.
- 테스트를 지우거나 건너뛰어 통과시키지 않는다.
- 주식 앱 파일과 키·계좌 정보에 손대지 않는다.
