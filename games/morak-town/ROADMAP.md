## 0. 이 문서의 효력과 개발 목표

이 개정안은 원안의 개발 순서와 충돌하는 설계 규칙을 대체한다. 원안은 별도 참고 파일로 보존한다. 원안의 ‘완료’ 표시는 사용자 제공 문서의 기록이며, 이번 작업에서 코드나 실행 화면을 검증한 결과가 아니다. 실제 저장소와 DEVELOPMENT.md는 제공되지 않았으므로 구현 착수 시 확인한다. 이번 산출물은 계획서 개정이며 게임 코드 변경이 아니다.

**목표: 사용자가 제공한 11장 레퍼런스의 선·색·비례·생활감·공간 밀도를 충실히 구현한 해안 소도시에서, 매장 배치와 사람의 이동이 공급·소비·고용·임대료에 연결되는 F&B 운영 시뮬레이션.**

‘니펫츠풍 소품을 몇 개 넣었다’는 완료 판정이 아니다. 시각 기준을 통과하지 않은 상태에서 콘텐츠 수를 늘리지 않는다. 문서만으로 시각적 완벽성을 보증할 수 없으므로, 실제 렌더를 레퍼런스와 비교하는 필수 검수 절차로 요구를 집행한다. 원작의 구체적인 건물·캐릭터·배치를 복제하는 대신 제공 이미지에서 관찰되는 조형 규칙을 신규 자산 전체에 적용한다.

### 유지할 핵심

- 가상 해안 도시 ‘모락 베이’, 한국 F&B 문화, 강 하구·바다·트램·광장.
- 장인 한 매장과 기업형 확장을 동등한 성장 경로로 제공.
- 임대 입점과 토지 매입·건축을 모두 초기부터 선택 가능하게 하되 자금·기간·위험 차이를 명확히 표시.
- 날씨·계절·교통·공급망·경쟁사가 실제 운영 결과에 영향.
- 회사 자금과 개인 자금 분리, 일시정지, 운영 위임, 모바일 대응.

## 1. 아트 디렉션 — 최우선 필수 조건

### 1.1 레퍼런스의 역할

| 제공 이미지 | 추출할 기준 | 적용 대상 |
|---|---|---|

레퍼런스에는 직선형 건물과 도로가 많다. 요구하는 곡선은 해안선·산책로·광장 가장자리·화단·테라스에 추가한다. 모든 건물과 길을 둥글게 바꾸는 것은 레퍼런스 충실도와 다르다.

### 1.2 반드시 지킬 시각 문법

1. **시점:** 원근 축소가 거의 없는 고정 평행 투영. 도시와 실내가 동일한 투영 기준을 공유한다. 초기에는 카메라 회전을 제공하지 않는다. 확대·이동·벽 걷기로 관찰한다.
2. **선:** 검정 대신 짙은 적갈색 외곽선. 둥근 연결부와 끝처리. 건물 외곽·내부 구조·미세 디테일의 3단계 선 굵기. 손맛은 고정된 자산의 형태에 넣고 프레임마다 흔들리는 노이즈는 사용하지 않는다.
3. **색:** 크림, 머스터드, 코랄, 더스티 핑크, 라벤더, 올리브, 청록을 중심으로 팔레트 제한. 출발점 예시: 잉크 #6B2225, 크림 #F7EDCE, 머스터드 #DFB964, 코랄 #D96D60, 핑크 #CC7998, 라벤더 #A497C3, 올리브 #999D70, 청록 #39AFAD. 이는 스크린샷에서 추출한 확정 색상이 아니라 첫 시안용 값이며 비교 검수로 조정한다.
4. **명암:** 평평한 색면을 기본으로 면 방향에 따른 소수의 색 변화만 사용. 광택·사실적 재질·강한 입체 그림자·과도한 그라데이션 배제.
5. **비례:** 사람이 읽히는 크기의 문·창·가구, 단순한 얼굴, 가늘고 부드러운 팔다리. 큰 머리의 장난감형 인물로 일괄 변경하지 않는다.
6. **생활 디테일:** 컵, 책, 화분, 에어컨, 빨랫줄, 자전거, 옥상 의자, 새 등을 장소의 용도에 맞게 배치. 같은 소품을 모든 건물에 무작위로 붙이지 않는다.
7. **여백:** 건물 사이 중정, 도로변 쉼터, 해변, 광장, 매장 통로를 실제 사용 가능한 공간으로 남긴다. 디테일의 밀도와 건물 점유 밀도를 구분한다.
8. **UI:** 크림 패널과 잉크 선화 아이콘. 숫자·가격·수량은 가독성이 높은 한글 폰트. 손글씨 느낌은 제목·간판에 제한하고 모든 화면을 장식체로 채우지 않는다.

**(사용자 결정으로 수정)** 유럽풍을 유지한다. 망사르드·박공지붕·석조 블록을 기본 문법으로 쓰되, 모든 건물을 같은 지붕으로 덮지 않는다. 구역마다 평지붕+옥상 생활, 박공, 망사르드의 비율을 다르게 두어 레퍼런스의 낮은 스카이라인·생활감·여백과 함께 읽히게 한다. 검수 기준은 '유럽풍인가'가 아니라 1.2의 1~8항이다.

### 1.3 자산 제작과 배치 자유의 타협

- 자산마다 실제 바닥 점유 형태, 출입구, 이용 지점, 가림 영역, 그림의 기준점, 지원 방향을 기록한다.
- 건물·기계·선반은 입체로 보이도록 그려진 이미지다. 이를 화면에서 평면 회전하면 시점이 무너지므로 지원 방향별 자산을 사용한다.
- 자유로운 위치 이동은 기본 제공. 방향이 중요한 가구는 초기 4방향, 검증 후 8방향으로 확장한다. 원형 테이블·화분 등 방향 영향이 작은 물체는 연속 회전을 허용할 수 있다.
- 곡선 도로변 건물은 지원 방향을 유지하며 앞마당·계단·테라스로 도로와 연결한다. 임의 방향 건물이 꼭 필요한 구간은 전용 자산을 제작한다.
- 생성 이미지를 사용할 경우도 기준점·투명 여백·선 굵기·방향·색·애니메이션 연속성을 후처리하고 검수한다. 이미지 한 장 생성으로 게임 자산 제작이 끝났다고 간주하지 않는다.

먼저 거리, 실내, 해변 3개 기준 장면을 만든다. 각 장면은 도시 전체 보기·기본 플레이·최대 확대에서 확인한다.

- [ ] 레퍼런스와 현재 렌더를 나란히 놓은 비교 이미지와 차이 목록을 남긴다.
- [ ] 가구 수를 늘리거나 색만 바꾼 것으로 미감 통과를 대신하지 않는다.
- [ ] 지붕·앞벽 걷기 상태에서도 사람·가구 가림이 정상이다.

## 2. 공간 설계 — 직선의 명료함과 곡선의 여유

### 2.1 도시 형태

지형 → 주요 장소 → 보행 연결 → 도로 연결 → 필지 → 건물 → 생활 소품 순으로 만든다.

해안·강·언덕을 먼저 확정하고 항구, 시장, 트램 정류장, 주거지, 광장, 공원을 배치한다. 짧은 직선 상업가로는 매장의 전면을 읽기 쉽게 만들고, 강변·해변 산책로와 공원길은 완만한 곡선으로 잇는다. 부채꼴·사다리꼴·불규칙 필지와 중정을 허용한다. 직각 격자와 곡선만 있는 미로 모두 피한다.

초기 지도 면적 배분 실험값은 건물 바닥 30%, 도로·보행로 25%, 공원·광장·중정·완충 공간 25%, 물·해변 등 자연 지형 20%다. 고정 정답이 아니라 체감 밀도를 비교하기 위한 출발점이다. 상업가는 더 밀집할 수 있지만 도시 전체를 빈틈없이 채우지 않는다.

도심은 보행 중심의 작은 거리로 구성한다. 대규모 생산시설·물류단지는 외곽 연결 지역에 배치해 핵심 해안 풍경을 침범하지 않는다. 접근 가능한 확장 지역으로 성장 규모를 늘린다.

### 2.2 지형과 도로 데이터

- 지도 원본: 연속적인 월드 좌표. 도로는 폭·곡률·통행 모드·속도·수용량을 가진 선과 교차점 그래프. 필지·바닥·공원은 폴리곤.
- 곡선은 제어점으로 편집하며, 렌더링과 이동 경로 모두 같은 원본에서 생성한다. 도로 그림만 둥글고 차량은 직각으로 꺾이는 구현 금지.
- 내부 공간 검색 격자는 유지할 수 있으나 사용자 배치 단위나 도로 형태를 강제하지 않는다.
- 차도, 인도, 자전거길, 횡단보도, 매장 출입 연결을 분리한다. 차도 연결과 보행 연결은 서로 다른 검사 대상이다.
- 곡선의 안쪽 인도 겹침, 교차로 틈, 지나치게 짧은 선분, 급회전, 자기 교차를 생성·편집 시 검증한다.
- 차량은 교차로 회전 경로를 따라 이동하고 보행자는 횡단 연결을 사용한다. 해변·공원에는 차량 길이 없어도 된다.
- 막다른 골목은 휴식·주거·서비스 공간으로 허용한다. 모든 길이 무조건 순환할 필요는 없지만 사용 중인 매장은 유효한 출입·배송 경로를 가져야 한다.

### 2.3 플레이어의 자유

공공 도로는 시청 소관, 소유 필지의 마당·보행로·테라스·가구는 플레이어 편집 가능. 자유 건축 모드에서는 공공 도로 편집까지 열 수 있다. 경제 모드는 소유권과 공공 연결을 유지한다.

편집 도구: 선택·이동·회전·복제·곡선 제어점·폭 조정·실행 취소·재실행. 격자 스냅은 끌 수 있고 벽면·모서리·인접 물체 정렬 스냅을 별도로 제공한다. 모바일은 끌기 외에 선택 후 위치·방향 조절 버튼을 제공한다.

변경 전 공사비, 좌석 변화, 통로, 접근성, 배송 경로, 예상 휴업을 미리 보여준다. 저장 불가능한 배치의 원인을 화면에서 표시한다. 장애물을 약간 놓았다는 이유로 도시 전체 경로를 다시 계산하지 않고 영향 구역만 갱신한다.

### 2.4 자유 인테리어

주방·홀·창고·테라스는 폴리곤 영역과 기능 태그로 정의한다. 주방 25~40% 같은 고정 비율을 강제하지 않고 설비·작업 공간·청결·처리량으로 판단한다. 구역별 권장 기능과 부적합 배치의 결과를 설명한다.

가구에는 장식 외곽과 실제 충돌 영역을 구분한다. 의자는 착석 위치와 접근 방향, 카운터는 직원 작업면과 고객 대기면, 기계는 조작·정비 여유를 가진다. 배치 확정 시 출입구→주문→좌석→퇴장, 입고→창고→조리→서빙 흐름이 이어지는지 검사한다.

좌석 수 증가가 매출 증가를 보장하지 않는다. 통로 협소→서빙 시간 증가→대기·이탈 증가로 이어져야 한다. 넓은 통로, 조용한 중정, 바다 전망도 타깃 고객과 운영 방식에 따라 가치가 생긴다.

### 2.5 밀도 5단계 재정의

밀도는 층수만이 아니라 필지 점유, 공실률, 영업 면적, 가구 수, 복합 용도로 결정한다. 초기 시각 상한은 핵심 해안 구역 1~3층, 일반 상업 구역 2~5층으로 제안하며 기준 장면에서 확정한다. 단계가 오르면 테라스 활용, 상층 공방·주거, 중정 상가, 복합시설로 변하고 모두 초고층이 되지 않는다.

- [ ] 같은 기능의 길을 직선·곡선으로 연결해도 출입과 배송이 가능하다.
- [ ] 사선·곡선 경계 필지에서 타일 모양 틈 없이 건물·마당을 배치할 수 있다.
- [ ] 스냅을 끈 가구 배치가 저장·불러오기 후 같은 위치에 남는다.
- [ ] 막힌 출입구, 겹치는 가구, 접근 불가 좌석을 확인하고 수정할 수 있다.
- [ ] 실제 이용 면적에 근거한 인구와 교통이 생성된다.

## 3. 유기적 경제 — 모든 효과를 거래와 제약에 연결

### 3.1 경제의 공통 기반

경제 주체는 가계·매장·공급자·물류업체·건물주·은행·시청·외부 시장이다. 가계는 예산과 시간, 매장은 재고와 인력·설비, 공급자는 생산량·재고·납기, 건물주는 공실과 계약을 가진다.

실제 거래마다 구매자, 판매자, 품목, 수량, 단가, 세금, 결제 시점, 배송 상태를 기록한다. 돈은 상대 계정으로 이동하고 원재료는 생산·판매·폐기·이송 중 명시된 경로로만 변한다. 관광객 지출, 외부 수출, 수입 결제, 대출 생성·상환은 외부 부문 또는 금융 계정에 기록한다. 도시를 억지로 완전 폐쇄 경제로 만들지 않되 자금 유입·유출을 숨기지 않는다.

기본 계정: 회사 현금, 개인 현금, 재고, 설비·건물, 매출채권·매입채무, 대출, 세금예수금. 손익과 현금흐름을 처음부터 구분한다. 회사→개인 이체는 급여·배당·대여 등 유형을 명시하고 단순 현금 복제를 막는다.

### 3.2 소비 수요 — 유한한 지갑과 유한한 시간

인구를 페르소나별 집단으로 계산하고 단골 등 일부 인물만 개별 상태로 유지한다. 직업·소득·연령·취향은 별도 속성으로 두어 ‘대학생은 맛을 무시한다’ 같은 고정 단정 대신 가중치 분포를 사용한다.

각 집단에 월 가처분소득, 식비 예산, 방문 가능 시간대, 이동 시간 한도, 외식 욕구가 있다. 선택지는 경쟁 매장뿐 아니라 집밥·구매 보류·다른 지역 방문을 포함한다.

매장 선택 효용 = 취향 적합 + 기대 품질 + 경험·단골 신뢰 + 공간 선호 − 가격 부담 − 이동 부담 − 예상 대기 − 혼잡·소음.

후보 매장 사이에서 수요를 배분한다. 인지도가 오른 매장은 다른 매장에서 고객을 가져오거나 구매 보류 고객을 설득할 수 있지만 도시의 소비 예산을 무한히 늘리지 못한다. 관광·고용 증가가 있을 때만 그에 맞는 외부 수요·소득 증가를 따로 반영한다.

### 3.3 주문과 실제 매출

주문은 접수→재료 확보→조리→제공/배송→완료 또는 취소 상태를 가진다. 재료 예약은 동시 주문의 중복 사용을 방지하고 사용·취소 시 정확히 반영한다.

실제 처리량은 수요, 레시피별 재료, 조리 작업대, 직원 작업 시간, 좌석 회전, 포장·배송 용량에 의해 제한된다. 장비 수를 단순 합산해 처리량을 정하지 않고 필수 공정 중 병목을 찾는다.

매출은 완료 거래에 근거하고 환불·할인은 원장에 남는다. 음식은 배치별 원가·수량·신선도·보관 조건을 가진다. 폐기·도난·조리 손실은 숨은 수치 감소가 아니라 별도 기록이다.

### 3.4 공급·가격·품질

공급자는 유한한 생산능력과 판매 재고를 가진다. 납품 계약은 단가·품질 범위·물량·납기·결제 조건·취소 비용을 포함한다. 경쟁사도 같은 공급량을 두고 거래한다.

시장가격은 생산 원가, 재고 대비 예상 수요, 계약 잔량, 수입 대체 가능성을 반영해 목표가격으로 점진 조정한다. 조정 속도와 일일 변동 제한을 설정하고 충격 후 과잉 생산→가격 하락 같은 회복 경로도 만든다. 모든 원재료가 같은 이벤트 배율로 동시에 움직이지 않는다.

국산 대체재는 자동으로 유리해지지 않는다. 대체 가능 요리, 전환 비용, 품질 차이, 국내 공급 여력과 가격을 확인한다. 원안의 ‘환율 상승→국산 고급재 수혜’는 조건부 결과로 수정한다.

### 3.5 공간과 경제 연결

| 공간의 변화 | 직접 결과 | 후속 경제 효과 |
|---|---|---|
| 넓은 보행로·곡선 산책로 | 접근성과 산책 체류 변화 | 시간대별 방문 후보 증가, 이동 우회 시 일부 감소 |
| 중정·그늘·해변 테라스 | 날씨별 좌석 선호와 체류 변화 | 객단가·회전율의 상충 |
| 과도한 좌석 배치 | 작업 동선과 이동 시간 증가 | 제공 지연·이탈·재방문 감소 |
| 배송 출입구 분리 | 고객과 배송 충돌 감소 | 납품 안정·직원 시간 절약 |
| 주차·트램 개선 | 교통수단별 도달 범위 변화 | 방문 가능 고객 구성 변화 |
| 인기 거리 개발 | 임차 수요 증가 | 계약 갱신 시 임대료 압력, 공실·이탈로 조정 |

‘곡선 도로 +10% 매출’처럼 형태 자체에 보너스를 주지 않는다. 형태가 실제 접근·쾌적함·사용 면적에 미치는 결과를 계산한다.

### 3.6 시간 지연과 안정 장치

경제 갱신은 명시된 순서로 실행한다: 외부 조건·일정 → 소득·생산·배송 → 방문 선택 → 주문·작업 → 결제·재고 → 평판·회계 → 다음 기간 의사결정. 같은 단계 안에서 매장 배열 순서 때문에 한 매장이 항상 재고를 선점하지 않도록 요청을 모은 뒤 공정하게 배분한다.

임대료는 계약 갱신 때, 고용은 채용·퇴사 후, 생산량은 발주·생산 기간 후 변한다. 즉시 상호 증폭하는 순환을 만들지 않는다. 가격·평판·입지 인기는 감쇠, 포화, 전환 비용을 가진다. 경기 사건은 발생 조건·기간·해제 조건·회복 경로를 모두 정의한다.

### 3.7 화면 속 사람과 시뮬레이션의 일치

모든 시민을 화면에 그리지는 않는다. 실제 집계된 이동·주문에서 대표 보행자·차량을 추출한다. 화면 밖 거래도 같은 규칙을 사용하고 화면 확대 여부가 매출을 바꾸지 않는다. 그래픽용 손님이 추가 주문을 생성하거나 장식 트럭이 재고를 두 번 채우면 안 된다.

혼잡·배달 시간은 경로와 교통 용량에서 산출한다. 신호·차량 애니메이션은 해당 상태를 표현한다. 기본 속도 하루 1분에서는 게임 시각의 짧은 신호 주기가 화면에서 깜박일 수 있으므로 시뮬레이션 시간과 관찰용 표현을 설계해 검증한다. 확대 관찰용 저속과 일시정지를 제공하고, 표현 보정이 회계 시간이나 배송 기한을 변경하지 않게 한다.

### 3.8 경제를 설명하는 UI

매장 매출을 방문 수 × 구매 전환 × 실제 처리율 × 객단가로 분해한다. ‘오늘 매출 감소’에는 재고 부족·손님 감소·대기 이탈 등 실제 원인 상위 3개를 표시한다. 근거 없는 조언 대신 ‘우유 부족으로 주문 8건 취소’처럼 기록을 연결한다.

가격·채용·발주·배치 변경 전에 예상 범위와 비용을 보여준다. 예측은 불확실성을 포함하며 미래 사건을 정답처럼 알려주지 않는다. 손실 뉴스마다 대체 공급, 메뉴 변경, 단축 영업, 발주 조정 등 실행 가능한 선택지를 연결한다.

### 3.9 경제 완료 기준

- [ ] 내부 거래의 지급·수취, 생산·소비·폐기·재고 이동이 대사된다. 금융·외부 거래는 별도 계정으로 설명된다.
- [ ] 같은 시드·같은 명령에서 저장 전후 결과가 재현된다.
- [ ] 재료 0인 메뉴 판매, 중복 결제, 음수 재고, 무한 고객 생성이 없다.
- [ ] 매장 1개를 10개로 늘려도 기존 지역 소비력이 자동으로 10배가 되지 않는다.
- [ ] 가격 인상·동선 악화·공급 중단에 예상 방향의 반응이 있으며 수치 원인을 확인할 수 있다.
- [ ] 경기 충격 제거 후 재고·가격·평판이 설정된 지연을 거쳐 회복한다.
- [ ] 카메라 위치·렌더링 빈도·대표 인물 수가 경제 결과를 변경하지 않는다.

## 4. 콘텐츠를 경제 위에 쌓는 방법

### 메뉴·장인 경로

초기 실험은 식재료 12~20종, 메뉴 틀 3종, 조리법 4종으로 시작한다. 원안의 60~80종은 조합의 재미와 재고 운영이 확인된 다음 확대한다. 발견은 완전 무작위 대신 재료 속성·조리법·셰프 지식에 근거하고 실패에도 힌트를 준다. 메뉴명 키워드 반복만으로 관광·SNS 보너스를 얻지 못하도록 실제 재료·지역 연관을 확인한다.

장인은 품질 일관성·단골·제자·지역 기여로 성장한다. 높은 명성이 가격 저항을 무한히 없애지 않으며 좌석과 작업 시간이 성장의 제약이다. 하나의 가게로도 독립 엔딩이 가능하다.

### 기업·경쟁사

표준화는 편차를 줄이되 재료·직원·물류 차이를 완전히 제거하지 않는다. 기업은 조달과 교육에서 규모의 이익을 얻는 대신 관리비·가맹 분쟁·품질 감시·매장 간 고객 잠식이 늘어난다. 경쟁사는 플레이어와 같은 현금·공간·재고 제약을 적용한다. 파산·신규 진입도 자금 출처와 정리 과정을 가진다.

경쟁사 0~50 설정은 유지하되 초기 검증은 3개에서 시작한다. 독립 맛집·가맹점·기업 수를 구분해 ‘경쟁사 50’이 실제 매장 50인지 기업 50인지 명확히 정의한다.

### SNS·셰프·미디어

SNS는 잠재 고객의 인지와 기대를 바꾼다. 노출→관심→방문 의향→실제 방문→재방문의 전환을 분리한다. 도달 가능 인구와 소비 예산 상한을 적용하고 반복 노출은 포화된다. 매체 보너스와 SNS 보너스로 같은 고객을 중복 생성하지 않는다.

셰프는 자동 우위 카드가 아니라 기술·성장·급여·업무량·관계가 있는 인력이다. 방송, 평가, 인플루언서는 실제 품질·서비스·기록에 반응한다. 모든 주민에게 개별 SNS 계정을 상시 계산하지 않고 중요한 인물과 대표 게시물을 생성한다.

### 생산·거시경제·주식

생산시설은 소매 재고·계약 체계가 안정된 뒤 연결한다. 처음에는 외부 공급자로 존재하고 이후 플레이어 소유와 B2B 판매를 연다. 수직계열화에는 투자비·고정비·가동률·기회비용이 있다.

거시경제는 산업 고용·수입 원가·관광·금융 비용의 외부 조건부터 시작한다. 주식은 회계·부채·실적·기대 변화 위에 추가한다. 사건 하나로 관련 주가 방향을 무조건 확정하지 않는다. 자사주 거래로 기업 현금이 생기는 것은 신주 발행 등 실제 자금 조달에서만 가능하고 일반 주주 간 거래와 구분한다.

### 세무·노동·보험·정책

초기에는 명시된 가상 게임 세율·계약 규칙으로 일관된 정산을 구현한다. 원안의 실제 세율·임대차 보호기간·신고 일정은 이번 개정안에서 현행 법률로 확인하거나 채택하지 않는다. 현실 제도 모드를 도입할 때 공식 자료·기준일·테스트를 별도 관리한다.

세무 대행은 업무 자동화·정확성·적용 가능한 공제 지원으로 구현하고 ‘전문성만큼 세금 일괄 할인’하지 않는다. 직접 신고 실패를 무작위 벌금으로 만들지 않는다. 노동 공급·임금·근무시간·피로는 초기 고용 모델에 포함하고 세부 법무·감사는 후속 확장한다.

시청도 예산·공사 기간·부지·운영비 제약을 가진다. 정책을 예고하고 이유·편익·부작용을 표시한다. 플레이어의 소유 부지나 매장 접근로를 설명 없이 변경하지 않는다. 도로 재편 시 우회·보상·공사 영향을 처리한다.

### 첫 플레이 구간의 구체적인 모습

직선 상점가 끝에서 완만한 해변 산책로와 작은 광장으로 이어지는 동네. 플레이어는 카페 겸 식당을 임대하거나 작은 필지에 건축한다. 가구를 자유롭게 배치하고 메뉴·가격·발주·근무표를 정한다. 점심에는 직장인, 오후에는 산책객이 오고 비가 오면 테라스 수요와 배송 상태가 바뀐다. 작은 매출 보고서에서 그 이유를 읽고 다음 날 결정을 바꾼다.

첫 구간의 성공은 ‘기능 버튼이 많다’가 아니라 **예쁜 동네를 관찰하는 즐거움, 배치의 자유, 운영 선택의 결과**가 한 플레이 안에서 모두 느껴지는 것이다.

## 6. 기술 설계와 검증

### 구조

기존 js/sim.js·render.js·ui.js는 실제 존재와 의존성을 확인한다. 시뮬레이션은 화면·오디오와 분리해 고정된 시간 단계로 실행하며 렌더링은 상태를 읽는다. 필요에 따라 world(도로·필지), economy(원장·수요·재고), operations(주문·직원), agents(경쟁사·정책), persistence(저장·이관)로 분리한다. 작은 시제품에서 무조건 대규모 재작성하지 않는다.

시드 난수, 명령 기록, 저장 가능한 이벤트 큐, 고유 ID를 사용한다. 금액은 최소 화폐 단위 정수, 수량은 명시된 정밀도로 기록해 부동소수 오차를 관리한다. 시뮬레이션 시계는 하나이며 정지 시 이동·배송·생산·급여 계산이 모두 정지한다.

### 렌더링과 성능

정적 지형은 청크 캐시, 건물·가구는 자산 캐시, 동적 인물은 별도 레이어로 유지한다. 곡선 도로 편집과 건축 변경 시 영향 청크만 무효화한다. 사람은 발 위치 기반 깊이 정렬을 사용하되 긴 벽·큰 가구는 가림 단위를 분할해 단순 Y 정렬의 오류를 보완한다. 확대에 따른 벽 걷기는 히스테리시스를 두어 경계에서 깜박이지 않게 한다.

화면 밖 이동은 집계하고 화면 안은 대표 개체로 표현한다. 공간 색인·경로 캐시·지역별 갱신을 사용한다. 전체 타일 순회를 피하는 것만으로 충분하지 않으며 수요 후보 검색·회계 집계·경쟁사 의사결정도 측정한다. Web Worker 전환은 프로파일링 결과와 상태 전달 비용을 보고 결정한다.

성능 목표 초안: 데스크톱 60fps, 대상 모바일 30fps 이상. 지원 기기·브라우저·도시 크기·경쟁사 수·배속을 함께 기록하고 평균뿐 아니라 p95 프레임 시간과 명령 반응 시간을 측정한다. 목표 미달이면 대표 인물·미세 장식·캐시 해상도를 조정하되 경제 계산과 핵심 그림체는 유지한다. 실제 대상 기기 선정 전 성능 달성을 선언하지 않는다.

### 저장

schemaVersion, mapVersion, contentVersion을 분리한다. 저장에는 연속 좌표·방향·계약·재고 배치·명령 상태·난수 상태를 포함한다. 자동 저장을 회전 보관하고 이관 전 사본을 남긴다. 구지도 변환이 불가능하면 이유를 설명하고 구버전 유지 또는 새 도시로의 명시적 이전 선택을 제공한다. 조용히 삭제하거나 버전 숫자만 보고 거부하지 않는다.

### 필수 테스트 묶음

1. 도로: 직선·급곡선·삼거리·교량·막다른 보행로·편집 후 경로 유효성.
2. 배치: 회전별 점유·문 접근·좌석 접근·대기열·출입구 차단·실행 취소·저장 복원.
3. 경제: 원장 대사·재고 보존·부분 배송·품절·취소·환불·대출·임차료·경쟁 수요 분배.
4. 시나리오: 공급 중단, 원가 상승, 우천, 관광객 증가, 임대 갱신, 과잉 출점, 인력 부족. 고정 시드와 대조 실행을 비교한다.
5. 장기 실행: 여러 시드에서 365일·900일 실행. 파산률·매장 수·현금 집중·공실·가격 폭주·수요 소멸을 분석한다. 원안의 ‘900일 60매장·613억’만으로 적정 난이도를 판단하지 않는다.
6. 화면: 기준 장면, 확대 단계, 야간, 계절, 메뉴 열림, 편집 상태를 데스크톱·모바일에서 확인. 의미 있는 동적 차이는 허용하고 투영·가림·선 굵기 오류는 회귀로 처리한다.

점검 명령 `node games/morak-town/test/sim.test.cjs`는 저장소에서 경로를 확인했고 통과한다(P0_STATUS.md 참고).

## 8. BM 재검토안 — 승인 전 구현 보류

원안의 사용자 지정 유료 보너스는 기록으로 보존한다. 다만 절세율, 고급 산지 공급권, 셰프 능력, 분석 도구를 결제로 우대하면 운영 결과가 경제적 판단보다 구매 여부에 좌우될 수 있다. 이번 개정에서는 삭제를 확정하는 대신 다음 방향을 제안하며, 결제·상점 구현은 P7에서 별도 결정한다.

- 기본 운영 위임, 원인 분석, 안전한 저장은 핵심 게임 기능으로 제공.
- 우선 검토: 외형·간판·의상·계절 장식·사운드·새 지역·시나리오.
- 기능성 유료 항목을 유지한다면 무료로도 동일 목표 달성 가능 여부, 경제 우위의 누적, 공급 독점, 장인 경로 영향까지 검증한다. 단순 ‘+8% 상한’만으로 균형을 보증하지 않는다.
- 원안의 가상 상점은 실제 결제와 분리하고 플랫폼을 정하기 전에 결제 가능·불가능을 단정하지 않는다.
